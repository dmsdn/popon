# 팝온 현장 체크인 (checkinfrontend)

팝업스토어 입구에 놓아두는 **태블릿용 현장 웨이팅 · 입장 화면**이에요.
손님은 앱 설치나 로그인 없이 직접 웨이팅을 등록하고, 직원은 같은 기기로 입장 QR을 찍어요.

> 담당: **박은우** (화면 설계 · 프론트엔드 구현)

## 기술 스택

| 구분 | 사용 기술 |
|---|---|
| 프레임워크 | Next.js 15 (App Router), React 19 |
| 언어 | TypeScript |
| 스타일 | Tailwind CSS 4 (다크 모드 고정) |
| QR 인식 | jsQR (카메라 프레임 실시간 분석) |
| 배포 | `output: "export"` 정적 빌드 → nginx 서빙 |

<br>

## 화면 흐름

```
/ (주최자 로그인)
 └─ /select-popup (운영 중인 팝업 선택)
      ├─ [웨이팅 시작하기] → /checkin?popupId=X       손님이 직접 등록
      └─ [QR 입장 찍기]   → /checkin/scan?popupId=X  직원이 입장 처리
```

두 버튼 모두 **브랜드 계정 비밀번호를 한 번 더 확인**한 뒤 진입해요. 손님이 쓰는 기기라서, 손님이 실수로 관리 화면으로 넘어가지 않도록 막는 장치예요.

<br>

## 주요 기능

### 손님용 웨이팅 등록 (`/checkin`)
- 가로형 태블릿 레이아웃: 왼쪽에 **현재 대기 팀 수 · 예상 대기시간**(5초마다 갱신), 오른쪽에 등록 폼
- **인원 선택 → 연락처 입력 → 이용 동의 → 웨이팅** 단계형 흐름
- 전화번호 **또는** 이메일 중 하나만 입력해도 등록 가능 (이메일은 아이디 + 도메인 드롭다운)
- 한국어 · English · 中文 · 日本語 4개 언어 전환 (외국인 방문객 대응)
- 등록 완료 시 대기번호 안내, 입장 QR 링크는 문자 · 메일로 발송 (백엔드 발송 계정 설정 시)
- 왼쪽 하단에 **소비자 앱 연결 QR**: 팝업 운영 방식(사전예약 / 웨이팅)에 맞춰 스캔하면 해당 화면이 바로 열림

### 직원용 QR 입장 (`/checkin/scan`)
- 화면이 열리면 카메라 자동 실행, 프레임 단위로 QR 인식 → 즉시 서버에 입장 요청
- **예약 QR과 웨이팅 QR을 구분 없이** 하나의 엔드포인트로 처리 (통합 QR 체크인)
- 같은 QR 연속 인식 방지 (3초 쿨다운)
- 카메라를 쓸 수 없는 기기에서는 QR 값을 직접 입력하는 폴백 제공

## 구현하면서 고민한 부분

### 1. 손님 입력 부담 줄이기
처음에는 전화번호와 이메일을 모두 받았는데, 현장에서 두 가지를 다 입력하는 건 부담이 컸어요.
**둘 중 하나만 필수**로 바꾸고, 백엔드의 비회원 필수값 조건은 프론트에서 누락 값을 보완해 충족시켰어요.
또 연락처보다 **인원 선택을 먼저** 두어, 가장 쉬운 입력부터 시작하도록 순서를 바꿨어요.

### 2. 예상 대기시간을 "팀 수"가 아닌 "인원 수"로
팝업 정원은 사람 수 기준이라, 대기 팀 수만으로는 정확한 대기시간이 나오지 않아요.
대기 인원 · 정원 · 평균 체험시간을 기준으로 계산하고, **소비자 앱과 같은 공식**을 써서 두 화면의 숫자가 어긋나지 않게 맞췄어요.

### 3. 소비자 앱과 디자인 · 로직 통일
이메일 입력, 전화번호 포맷, 개인정보 동의 문구를 소비자 앱(customerfrontend)과 **같은 로직 · 같은 디자인**으로 구현했어요.
색상 토큰(포인트 `#5bce41`, 배경 `#17181a`, 카드 `#282b32`)도 그대로 공유해요.

### 4. 배포 환경에서 QR 주소가 깨지지 않게
배포 후 QR이 `localhost`를 가리키는 문제가 있었어요.
환경변수가 있으면 그 값을 쓰고, 없으면 **현재 접속 주소에서 소비자 앱 주소를 자동 유도**하도록 바꿨어요.
(배포: `checkin.<도메인>` → `<도메인>`, 로컬: `:5176` → `:5173`)

### 5. 태블릿 실사용 대응
- iOS Safari에서 버튼 눌림(`:active`) 효과가 안 보이는 문제를 터치 리스너 등록으로 해결
- 이메일 도메인 드롭다운은 스크롤바 대신 드래그로 스크롤 (터치스크린에서도 자연스럽게)
- 로그인 정보는 `sessionStorage`에 저장해, 태블릿을 켜둔 동안만 유지

## 폴더 구조

```
checkinfrontend/
├── app/
│   ├── page.tsx              # 주최자 로그인
│   ├── select-popup/         # 운영 중 팝업 선택 + 비밀번호 재확인
│   ├── checkin/page.tsx      # 손님용 웨이팅 등록 (가로형)
│   ├── checkin/scan/         # 직원용 QR 입장 스캔
│   └── TouchActivation.tsx   # iOS 터치 피드백 처리
├── lib/
│   ├── auth.ts               # 로그인 토큰 · 선택 팝업 저장
│   └── siteUrls.ts           # 소비자 앱 주소 유도
└── public/icons/             # 로고 SVG
```

## 실행 방법

```powershell
npm install
npm run dev
```

`http://localhost:5176`에서 열려요. 통합 백엔드(`localhost:8080`)가 켜져 있어야 로그인과 등록이 동작해요.

- 로컬 개발에서는 `next.config.ts`의 rewrites가 `/api`를 백엔드로 프록시해요.
- 배포 빌드(`npm run build`)는 정적 파일로 나오고, `/api` 프록시는 nginx가 맡아요.
- `NEXT_PUBLIC_CONSUMER_URL`(선택): QR이 연결할 소비자 앱 주소. 비워두면 자동 유도해요.
